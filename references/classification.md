# 分类约定

## 游戏与角色

- 使用游戏和角色的常用中文名称，同一角色的中英文名统一到同一目录。
- 依据实际图片，结合发型、发饰、瞳色和特有配件等特征识别。换装同人不能只凭服装判定。
- 不认识的角色保留待识别状态。需要查证时优先查询游戏官方角色资料，区分图像证据和文件名线索。
- 同一游戏的多名角色归该游戏的“多角色”，具体角色写入 evidence；跨游戏图片归“跨游戏/多角色”。
- 游戏已知但角色未知：`游戏/游戏名/待识别角色`。
- 确认是游戏图片但游戏未知：`游戏/待识别游戏/待识别角色`。

## 非游戏内容

kind 允许值：游戏、真人照片、原创或其他动漫、风景物品、截图文档、其他、待分类。

- 真实人物照片归“真人照片”，不推断真实身份。
- 来源不明的动漫图片归“原创或其他动漫”或“待分类”，不要强行归入游戏。
- 普通截图按截图文档处理；能确定游戏和角色的游戏截图可按游戏分类。
- kind、game、character 均为单个目录名，不得包含路径分隔符、盘符、`..` 或 Windows 保留名称。

## 状态与归档

| status | 含义 | 归档位置 |
| --- | --- | --- |
| verified | 已看图且有充分依据，或用户明确指定 | 对应分类目录 |
| proposed | 只有文件名等线索，尚未看图 | 待核实 |
| pending | 未查看或无法判定 | 待分类 |

labels.json 可只包含本批次判定；缺失 ID 自动保留 pending。无效或重复 ID、将重复副本作为代表图标注都会被拒绝。一个批次的 labels.json 仅对应生成它的 inventory.json，重新扫描后不可按旧编号套用。
